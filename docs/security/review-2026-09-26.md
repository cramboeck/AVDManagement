# Sicherheitsdurchsicht 26.09.2026

Gegenstand: die in dieser Iteration hinzugekommenen Teile (Apps C2/D,
winget-Quelle, Exchange-Postfachdetail, Worker-Endpunkte) gegen die
Sicherheitsanforderungen der Projektkonstitution (CLAUDE.md).

## Massstab

1. Keine Secrets in DB, Repo, ENV-Dateien im Repo oder Logs.
2. Jede schreibende Aktion ist ein Job mit Vorschau, Freigabe und Audit.
3. Vollstaendiges Audit mit Vorher/Nachher, auch fehlgeschlagene Versuche.
4. Keine personenbezogenen Daten in Logs oder Telemetrie.
5. Tenant-Isolation in jeder Abfrage.
6. Eingaben validiert, keine Pfad- oder Befehlsinjektion.

## Ergebnis

| Bereich | Befund | Stand |
|---|---|---|
| Worker-Token | Zeitkonstanter Vergleich, Mindestlaenge, nur Umgebungsvariable oder DPAPI-Datei, `worker.token` und `worker.config.json` in `.gitignore`, 503 ohne Token | in Ordnung |
| Worker-Endpunkte | Worker sieht nur Auftraege, die er selbst haelt (`worker_id` + Status); Artefakt-Upload nur fuer eigenen Auftrag; Log begrenzt | in Ordnung |
| Worker-Token installationsweit | Ein Token fuer alle MSPs einer Installation | Risiko SEC-005 aufgenommen; vor Mehr-MSP-Betrieb Token je MSP |
| Paketmanifest aendern | `PUT /packages/:id` hatte keinen Audit-Eintrag, obwohl Befehle darin als SYSTEM laufen | behoben: `apps.package.update` mit Vorher/Nachher der sicherheitsrelevanten Felder |
| Rollout-Vorschau | Zeigte bei Wrapper-Paketen nur die PSADT-Kommandozeile, nicht die Installer-Parameter, den Deinstallationsweg und die Quelle | behoben: Vorschau (und damit das Job-Audit) enthaelt Installer-Parameter, inneren Deinstallationsweg, Quell-URL und Hash |
| winget-Quelle | Nur https, SHA-256 Pflicht und vor dem Bauen geprueft, Id per Regex, GitHub-Token nur an api.github.com | in Ordnung; Risiko SEC-006 aufgenommen |
| Dateinamen | `..` oder `.` als Dateiname konnten den Sanitizer passieren (Speicherpfad und Worker-Arbeitsordner) | behoben: `safeInstallerFileName` im Core und `safeFileName` in der API ersetzen Punktfolgen, `assertSafeKey` bleibt zweite Sperre |
| Fehlerantwort Schema | Postgres-Fehlertext ging auch in Produktion an den Client | behoben: Detail nur in Entwicklung |
| Abwesenheitsnotiz | Formulartext ging als HTML an Graph | behoben: Text wird maskiert, Zeilenumbrueche zu `<br>` |
| Postfachdetail, Regeln | Jeder Abruf im Audit (`mail.mailbox.view`, `mail.forwarding.scan`); Aenderungen nur als Jobs; UPN per Regex und URL-kodiert; keine Inhalte in Logs | in Ordnung |
| Tenant-Isolation | Postfachrouten ueber Tenant-Middleware; Pakete an `mspId` gebunden; Rollout prueft Tenant-Zugehoerigkeit; Worker liest `mspId` aus dem Auftrag | in Ordnung |
| Artefakt im Speicher | Upload nach Intune haelt das ganze `.intunewin` im RAM | begrenzt auf 2 GB mit klarer Meldung; Stream-Upload im Backlog |
| Wrapper-Erzeugung | Alle Manifestwerte als einfach-quotierte PowerShell-Literale, Namen und Prozesse per Regex, Syntaxpruefung vor dem Packen | in Ordnung; der Deinstallationsbefehl ist bewusst freier Text (Manifest ist Code, siehe SEC-004) |
| Secrets | Keine neuen Secrets im Repo; `GITHUB_TOKEN`, `WORKER_TOKEN` nur in `.env.local` / Key Vault | in Ordnung |
